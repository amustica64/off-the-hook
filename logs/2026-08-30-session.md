**Tables.** All 13 Doc 06 section 3 content types are present, plus

### The real defect, found by the diff

Both survivors are `forms.spec.ts:46`, "referral form submits and the
candidate initial is enforced", on desktop and mobile. The server log gives
it without ambiguity:

```
referral submit failed: encryption key not configured
```

The chain, from `db/migrations/0001_rls_and_rpcs.sql`:

- `create_referral` encrypts the notes with `pgp_sym_encrypt(..., enc_key())`.
- `enc_key()` is:

```sql
-- Encryption key: Supabase Vault in production, GUC app.enc_key for local dev.
create or replace function enc_key() returns text language plpgsql stable as $$
declare k text;
begin
  k := nullif(current_setting('app.enc_key', true), '');
  if k is null then raise exception 'encryption key not configured'; end if;
  return k;
end $$;
```

The comment says Vault in production. **The function never reads Vault.** It
reads one GUC and nothing else. `db/client.ts` opens a plain `postgres()`
connection and sets no GUC, so `app.enc_key` is unset on every application
connection in every environment.

Consequences:

1. **Any referral carrying notes fails, everywhere, including on Supabase.**
   Not a local artefact.
2. A referral with the notes field empty would succeed, because the
   `case when coalesce(payload->>'notes','') = '' then null` branch never
   calls `enc_key()`. So the form fails only when a referrer writes the
   sensitive context the form exists to collect.
3. The RLS proof passes because it sets the GUC itself at line 47:
   `select set_config('app.enc_key', 'dev-only-key', false)`. The proof
   arranges the condition the application never arranges. That is why this
   survived eleven sessions.

This is on the safeguarding route, which Doc 09 section 3.13 and Doc 06
section 3.10 both treat as the most sensitive path on the site. It should be
the next thing fixed, ahead of any motion work.

The fix is a decision, not a keystroke, so I have not made it. Two shapes:
set the GUC per connection or per transaction from a server-side secret, or
make `enc_key()` genuinely read Supabase Vault and keep the GUC as the local
fallback the comment already promises. The second matches the comment and
Doc 07 section 9. Either way `.env.example` gains a key and Doc 07 section 7
gains a line, and neither exists today.

### How to bring the database back up

  -D <scratchpad>/pgdata stop

To start it again, or on a fresh machine: `npm i embedded-postgres@17.10.0-beta.17`
