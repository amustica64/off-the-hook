## What actually happened

The session was briefed as "scaffold Phase 1, then land six motion files". Five
of the brief's premises did not hold, so the shape of the work changed. Recorded
here because the next session will hit the same things.

1. **Docs 17 and 18 do not exist.** The pack runs 01 to 12 and stops. No
   document in it references a Doc 13, 17 or 18, and the only "17" anywhere is
   Doc 7 section 17, an email routing appendix. Every one of the six motion
   files cites Doc 17 as its authority. Decision taken this session: proceed
   treating the six files plus the QA register as the spec of record. Anything
   below marked "invented" was designed here, not quoted.

2. **Phase 1 was already built.** The project is a complete Next.js 15.5.22 and
   React 19 app matching the Section 2 locked stack: 33 routes, 24 components,
   Biome, Vitest, Playwright with 8 e2e specs, Drizzle, Fontsource. Running
   `pnpm create next-app` over it would have destroyed the work of ten previous
   sessions. What it needed was `pnpm install`, which had never been run. That
   is why nothing had ever compiled.

3. **Doc 7 section 4 is stale, and pasting it verbatim would regress the app.**
   The `@theme` block in `app/globals.css` is ahead of the doc, amended per
   Doc 12 section 6. Doc 7 lacks `--color-cream-25`, `--color-accent-fill`,
   `--color-accent-fill-hover`, `--color-accent-wash-text` and the five
   `--color-status-*` entries. It also writes `@theme` where the live file
   correctly writes `@theme inline`, and that difference is load bearing:
   without `inline`, Tailwind re-emits the values instead of resolving the
   references, so every alias that flips under `html[data-theme="dark"]` stops
   responding to the theme. The live block was kept. Doc 7 section 4 should be
   updated to match, not the other way round.

4. **`count-up.tsx` was not the reference pattern it was described as.** It
   predates the agreed fixes, calls `useReducedMotion` directly, hardcodes both
   a duration and a curve, carries no `data-reveal`, and names its boolean
   `reduced`, which is the exact shadowing the register exists to kill. It has
   been brought in line with the others rather than used as their model.

5. **Section 9's directory layout is superseded.** It specifies an
   `app/(public)/` route group and routes that do not match what is built.
   Doc 00 says Doc 12 wins on routing and not to re-argue it, so the built
   structure was followed.

## Tokens settled, so nobody has to ask again

`--bg`, `--text-primary` and `--text-secondary` are real. `app/globals.css`
already carries a full semantic alias layer, defined on `:root` and overridden
under `html[data-theme="dark"]`. `journey-line.tsx` was right to use them and
the register finding against it (J3) is withdrawn. The proposed fallback to
`--cream-50` / `--ink-900` / `--ink-500` must not be applied: it would hardcode
light values and break dark mode. Note `--text-secondary` is `--ink-700`, not
`--ink-500`, which is `--text-muted`.

## Register outcome

45 of 47 findings addressed. Two withdrawn on evidence from the first compile:

- **T1 disproven.** `easeEnter` has always been a readonly tuple under
  `as const`, is fed to framer, and the build passes. The same shape in
  `motionTokens` type checks.
- **H5 resolved by the library.** `progress()` in motion-utils 12.39 reads
  `return range ? (value - from) / range : 1`, so a zero width range returns 1,
  never NaN. The degenerate ranges were cleaned up anyway rather than left
  resting on a third party guard.
- **L5 confirmed and fixed.** `isMotionValue` is exactly
  `Boolean(value && value.getVelocity)`, so the hand written shim would have
  read as "not a motion value" to every framer path that asks. It only worked
  because `useCombineMotionValues` happens to call just `.get()` and `.on()`.

Four fixes collapsed several findings into one change each, as briefed:

- **X2 and N3** became `useMotionPreference()`, returning `{ isReduced, fade }`.
  Five call sites, one source, and the token set is never destructured to a bare
  `reduced` again, so the shadowing cannot come back.
- **X1 and X1b** became one `<noscript>` block in `app/layout.tsx`. The stroke
  resets are the half that matters: framer compiles `pathLength` to
  `stroke-dasharray` and `stroke-dashoffset`, so without them the rule reaches
  no line on the site. Verified present in the served HTML.
- **H3 and H4** both took the `active` value Hero was already computing and
  discarding. It now gates the headline reveal and drives `aria-hidden` plus
  `inert` on the non-active layers.
- **H1, H2 and N2** are one calculation: measure the stage element, not
  `window.innerHeight`, and use `getBoundingClientRect().top + scrollY`.

**N4 is invented, and flagged as such.** The cross dissolve fallback was
supposed to come from "Doc 17 section 7's hero decision record", which does not
exist. `useCanWarp()` asks `(update: slow)`, `hardwareConcurrency` and
`deviceMemory`, never the user agent, and starts `false` so the cheap path is
what the server renders and what an un-upgraded client keeps. The fallback is a
scale to `hero.dissolveScaleTo` (1.03) with an opacity cross dissolve, replacing
the 14px blur and the clip wipe. The threshold (8 cores) is a judgement call and
should be reviewed against real devices.

**P2 is scoped, not solved, and the file headers now say so.** `<noscript>`
covers scripting being disabled. It does not cover a bundle that 404s, a
hydration throw or a blocking extension, because JS is enabled in all three.
Covering those means not emitting the hidden state server side at all, which is
a larger change than this slice.

```

pnpm check   exit 1    11 errors, 7 warnings, identical to the baseline
                       taken before any edit. None are in the new or
                       modified files.

playwright (full suite)              26 passed, 24 failed, 2 skipped

The Phase 1 gate is proven: the tagline renders in Fraunces at the display
clamp, body background measures `rgb(250, 245, 233)` which is `--cream-50`, the
toggle sets `data-theme="dark"` and the background becomes `rgb(22, 18, 16)`
which is `--night-950`.

The 24 e2e failures are the absence of a database, not a regression. Postgres is
not running, `.env.local` points at `postgres://app:app@localhost/offthehook`,
and every reader in `lib/data/` degrades to `[]` by design. The failures are all
assertions on seeded content, and the journey one reads "Expected: 7,
Received: 0" because `JourneyTimeline` correctly returns `null` for an empty
list. `shell.spec.ts` failed in the full run and passes in isolation, so that
one was parallel load flake.

Honest limit on that claim: no e2e baseline was captured before editing, so the
attribution rests on the absence of Postgres, the shape of the assertions and
the isolation re-runs, not on a before and after comparison.
