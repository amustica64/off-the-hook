## 2. `/legal/*`, one template over six routes

This was item 8's blocker. `content/` did not exist, so six routes were stuck.

`app/legal/[slug]/page.tsx` is the single template Doc 09 section 3.23 asks for
("one template, six routes"). The six static stubs are gone. All six URLs are
unchanged and now prerender as SSG from `generateStaticParams`, at 168 B and
106 kB first load, which is the lightest content route on the site.

Built to Doc 04 legal section: slim H1, last-updated under it, narrow prose,
sticky contents rail on desktop only, breadcrumbs per Doc 03 section 7 with the
current page last and not a link, and no decoration.

Two things I decided rather than followed:

- **The grid in Doc 04 does not close.** It asks for prose at `col-span-8
  start-3` and the rail at `col-span-3 start-10`. In a twelve column grid those
  are columns 3 to 10 and 10 to 12, which collide on column 10. The prose starts
  one column earlier so the rail keeps the position the doc gives it. Written
  into the file rather than silently redrawn.
- **Metadata is a typed registry, not MDX frontmatter.** There is no YAML parser
  in the dependency tree. Hand-rolling one to read four fields is a worse trade
  than `LEGAL_DOCS` in `lib/content/legal.ts`, which the compiler checks and
  which shows all six documents' status in one place. Adding a dependency for
  this was not worth it.

Anchor ids for the contents rail and for the rendered H2s come from one shared
`headingId` helper, so a renamed heading cannot leave the rail pointing at
nothing. A test walks every rail link and asserts the heading exists.

### 2a. Two documents are written. Four are not, and say so.

This is the part I want you to look at hardest.

**Written, because they are derivable from facts I could verify in this
repository:**

- **Cookies.** Every claim on it was checked against the code before it was
  written. The site sets no cookies: there is no `cookies()` from
  `next/headers` and no `document.cookie` anywhere. Two browser storage keys
  exist, `theme` in local storage (next-themes, default key confirmed in the
  package) and `oth:intro-drawn` in session storage (`line-draw.tsx`). Fonts
  are self-hosted through `@fontsource`, so no font network sees a visitor.
  There are no analytics and no third-party scripts. The page says exactly that
  and nothing more.
- **Accessibility.** Also checked line by line: the skip link, the
  `*:focus-visible` outline, the `prefers-reduced-motion` block, `lang="en-GB"`,
  the noscript reveal that makes content readable without JavaScript, and
  labelled fields with inline errors. All present, all cited honestly.

  It deliberately **does not claim a WCAG conformance level**, because nobody
  has audited the site. It also says plainly that the automated axe run covers
  the component library at `/design` in both themes and not every page, which is
  what `design-axe.spec.ts` actually does. An accessibility statement that
  overclaims is worth less than none.

**Not written: privacy, safeguarding, CIC declaration, modern slavery.**

I did not draft these, and I want to be direct about why. A privacy notice names
a controller, an ICO position, retention periods and a lawful basis. A
safeguarding statement names a lead. A CIC declaration is a document filed at
Companies House. A modern slavery statement is board-approved and signed by a
director. None of those facts exist anywhere in the pack, and writing
plausible-looking text for any of them would produce an official-looking
document this organisation does not hold. That is the same error as the City and
Guilds certificate and the synthetic portrait retired yesterday, and it is worse
here, because a privacy notice makes promises about how a vulnerable person's
data is handled.

So those four routes render an honest unpublished state: the document is being
written, it is not published, ask us if you need it. They are `noindex` while
unpublished, and they carry no last-updated date, because claiming a date for a
document that does not exist is the small lie that makes the rest
untrustworthy.

**The safeguarding page is the one that could not just say "coming soon".** It
carries an extra line: if someone is in immediate danger, call 999, and if the
concern is about a person on the programme, use the referrals page and say it is
urgent. That route exists and works today.

**What each one needs before it can be published is written down**, per
document, in the `needs` field of `LEGAL_DOCS`. That is seven specific facts for
privacy, four for safeguarding, three each for the other two. It is deliberately
not rendered to visitors: a public list of what an organisation has not yet
decided about safeguarding is not a thing to publish. It is there so whoever
picks this up knows exactly what to ask for. Much of the privacy list is already
half-answered by the build itself (Supabase, Vercel, Cloudflare, the encrypted
referral notes), and the list says so.

## 3. `/contact`, built

Item 8, and the accessibility statement needed somewhere real to send a
complaint, which made this the next thing rather than a later thing.

Built to Doc 04 contact section and Doc 09 section 3.20: H1, one-line lead, four
audience router cards above the form, general form, phone and address at the
foot. The router line is verbatim as Doc 09 requires. No breadcrumbs, because
Doc 03 section 7 names `/contact` as a page where they would be noise.

`GeneralContactForm` is a new component because Doc 04 names it and gives it

and the person who lands on `/contact` is the one who did not fit a persona.

**`subject` has no column**, the same shape of problem as the booking form's
occasion field yesterday. It rides in `metadata`, labelled, which is what Doc 06
section 3.9 provides that column for. **No migration was needed**:
`submit_enquiry` already reads `payload->'metadata'` and already accepts the
`contact` type.

The phone and address block degrades honestly. Both live in `lib/venue.ts` and
both are unset, so the page says the line and the address are still being set up
and points at the form, rather than printing a number. I added `addressLines` to
`venue.ts` so the address has the same single home the phone number does.

## 5. What I could not verify, and did not pretend to

**There is no database in this environment.** `DATABASE_URL` points at
`localhost` and the connection is refused. There is no Postgres service on this
machine, no Docker, and no `supabase/` project directory, so I could not start
one. Yesterday's run had a database; this session did not.

That means **everything that writes a row is unverified by me today**, including
the contact form I just built.

The suite, run against a production build on a fresh port:

```
vitest                     4 passed
playwright        44 passed, 29 failed, 3 skipped
```

All 29 failures are database-backed by name: the form submissions, the seeded
stories, the menu prices, the impact tiles, the journey steps. My own new
submission test is one of them.

**One of those failures was mine and is fixed.** The contents rail test asserted
the rail on the mobile project, where Doc 04 deliberately hides it. It now skips
on mobile with that reason written in, which is why the skip count went from 2
to 3 and the pass count from 42 to 44.

**How far the contact form is actually proven.** The submission test drives the
real form, and the page comes back with "Something went wrong at our end", which
is the server action's own catch. So the form renders, validates, submits,
reaches the action, and fails at the database boundary and nowhere earlier. What
is **not** proven is the row landing in `enquiries` tagged `contact` with the
subject in `metadata`. **Run the e2e suite once a database is up before signing
`/contact` off.** I would not claim it before then.

Everything static was verified for real: all six legal routes return 200, an
unknown slug returns 404 and renders the branded not-found page rather than an
empty template, the drafts carry `noindex` and the published pages do not, every
contents rail link resolves to a heading that exists, and the four router cards
point where Doc 04 says.
